\section{Problem Statement}
%% ============================================================

The U.S. Environmental Protection Agency (EPA) oversees roughly 800,000 facilities under laws like the Clean Air Act (CAA), Clean Water Act (CWA), and Resource Conservation and Recovery Act (RCRA). But regulatory agencies only have so many inspectors and so much budget, and smaller facilities tend to get less attention than those classified as major sources. Small manufacturers, meaning those in NAICS sectors 31--33 that do not have a major regulatory designation, make up a large chunk of the regulated population. Compliance costs for these firms are significant too, exceeding \$50,000 per employee per year according to some estimates \cite{nam2023}.

The question we are trying to answer is: can we predict which small manufacturing facilities will have environmental compliance violations in the next year, based on their past compliance patterns and facility characteristics? If we can build a model that does this reliably, it could help regulators decide where to focus their inspections, and also help manufacturers understand what factors are associated with non-compliance.

We treat this as a binary classification problem. Using the EPA's Enforcement and Compliance History Online (ECHO) database, we construct a pseudo-temporal prediction setup by splitting each facility's 12-quarter compliance history string into a 2-year feature window and a 1-year target window. We then compare four classifiers (Logistic Regression, Random Forest, XGBoost, and SVM) and evaluate them with AUC-ROC, AUC-PR, and bootstrap confidence intervals. As far as we know, this kind of supervised learning approach has not really been applied to the small manufacturer segment of ECHO data for violation prediction.

\section{Data Description and Cleaning}
%% ============================================================

\subsection{Data Source}

The data for this project comes from the EPA ECHO Exporter, which is a weekly-updated bulk download containing facility-level summaries for all regulated establishments in the U.S. The full export file has 3,091,085 facilities across 133 columns, covering things like facility identification, geographic location, what regulatory programs they participate in, inspection and enforcement history, penalties, and quarterly compliance status.

\subsection{Population Filtering}

We applied the following filters to get to our target population:
\begin{enumerate}
    \item \textbf{Industry}: Kept facilities with at least one NAICS code in the manufacturing sectors (31, 32, or 33).
    \item \textbf{Size proxy}: Removed facilities flagged as major (\texttt{FAC\_MAJOR\_FLAG = Y}). We use non-major status as a rough proxy for smaller establishments since exact employee counts are not available in ECHO.
    \item \textbf{Activity}: Only kept active facilities (\texttt{FAC\_ACTIVE\_FLAG = Y}).
    \item \textbf{History completeness}: Required the full 12-quarter compliance history string to be present.
\end{enumerate}

After all of these filters, we ended up with about 120,000 small manufacturing facilities.

\subsection{Target Variable Construction}

The ECHO Exporter includes a field called \texttt{FAC\_3YR\_COMPLIANCE\_HISTORY}, which is a 12-character string where each character represents one quarter's compliance status over the past three years. Each character encodes one quarter: underscore (\texttt{\_}) for no violation, \texttt{V} for violation, \texttt{S} for significant non-compliance, and \texttt{U} for unknown. Position 0 is the oldest quarter and position 11 is the most recent.

We split this string to create a pseudo-temporal prediction problem:
\begin{itemize}
    \item \textbf{Feature window} (positions 0--7): the older 2 years, used to build our predictive features.
    \item \textbf{Target window} (positions 8--11): the most recent year. The binary target is 1 if any character in this window is \texttt{V} or \texttt{S}, and 0 otherwise.
\end{itemize}

This lets us simulate the real-world task of predicting next-year violations from historical data, even though we're working with a single cross-sectional snapshot. The resulting positive class rate is about 8.1\%, which is the moderate class imbalance we expected from our proposal.

\subsection{Data Leakage Prevention}

A number of fields in ECHO directly encode the full 12-quarter compliance history or current compliance status, which would leak the target variable if we included them. We excluded the following fields:

\begin{itemize}[nosep]
    \item \texttt{FAC\_QTRS\_WITH\_NC} (exactly equals the count of V/S across all 12 quarters)
    \item \texttt{FAC\_COMPLIANCE\_STATUS}, \texttt{FAC\_SNC\_FLG}
    \item All program-specific \texttt{*\_COMPLIANCE\_STATUS} and \texttt{*\_SNC\_FLAG} fields
    \item \texttt{FAC\_DAYS\_LAST\_INSPECTION}
\end{itemize}

We did keep cumulative lifetime counts like \texttt{FAC\_INSPECTION\_COUNT}, but ran a sensitivity analysis to check whether those introduce any soft leakage since they might include activity from the target period.

\section{Methodology}
%% ============================================================

\subsection{Preprocessing}

We used median imputation for the small number of missing values in \texttt{FAC\_PERCENT\_MINORITY} and \texttt{FAC\_POP\_DEN}, and filled program-specific counts with zero for facilities not in that program. For high-cardinality categoricals (\texttt{naics\_3digit} with around 80 categories, \texttt{fac\_state} with around 50), we used scikit-learn's \texttt{TargetEncoder}, which handles cross-fitting internally to prevent leakage during cross-validation. Lower-cardinality categoricals (\texttt{naics\_2digit}, \texttt{fac\_epa\_region}) were one-hot encoded. All numeric features were standardized with \texttt{StandardScaler}. The whole thing was wrapped in a \texttt{ColumnTransformer} so that transformations only get fit on training data.

We split the data 80/20 into training and test sets, stratified by the target variable.

\subsection{Models}

We trained four classifiers, picking models that cover a range of complexity and interpretability:

\textbf{Logistic Regression (L1).} This serves as our interpretable baseline. The L1 penalty does feature selection by pushing less useful coefficients to zero. We tuned the regularization strength $C \in \{0.001, 0.01, 0.1, 1, 10\}$ using 5-fold stratified CV with AUC-ROC scoring, and set class weights to \texttt{balanced} to handle the imbalance.

\textbf{Random Forest.} An ensemble of decision trees that works well with mixed feature types and gives us built-in feature importance. We tuned the number of trees $\{200, 500\}$, max depth $\{5, 10, 20\}$, and minimum samples per leaf $\{5, 20, 50\}$ via grid search with balanced class weights.

\textbf{XGBoost.} Gradient-boosted trees, which tend to do very well on tabular data \cite{chen2016}. We used \texttt{scale\_pos\_weight} for the class imbalance and tuned depth, learning rate, number of estimators, subsample ratio, and column sample ratio through randomized search over 30 configurations.

\textbf{SVM (RBF Kernel).} We included this to see whether a kernel-based decision boundary could improve classification. The main issue is that the RBF kernel has $O(n^2)$ memory requirements for the kernel matrix, so we could not train on the full dataset. We instead trained on a stratified subsample of 12,000 rows and evaluated on the full test set. We tuned $C \in \{0.1, 1, 10\}$ and $\gamma \in \{\text{scale}, 0.01, 0.001\}$.

\subsection{Class Imbalance Handling}

With about 8\% of facilities in the positive class, we compared three strategies using the best XGBoost config: (1) no weighting at all, (2) class weighting through \texttt{scale\_pos\_weight}, and (3) SMOTE oversampling applied inside the cross-validation loop using \texttt{imblearn.pipeline.Pipeline} so that synthetic samples only come from training folds.

\subsection{Sensitivity Analysis}

To check for potential soft leakage from the cumulative lifetime count features (which might include activity during the target period), we retrained XGBoost with and without those features. Dropping the cumulative counts lowered AUC-ROC from 0.974 to 0.926, a drop of 0.048. This is not nothing, but the model without those counts still gets strong discrimination (AUC $>$ 0.92), which tells us that the compliance history string features, which have a clean temporal split, are carrying most of the predictive signal. The cumulative counts add useful information on top of that rather than being pure leakage.

\subsection{Error Analysis}

We looked at the false negatives (facilities that violated but got predicted as compliant) and false positives (predicted to violate but stayed compliant) from the best model. The false negatives tend to be facilities that had fewer prior violations and less regulatory activity in their feature window. Basically they look a lot like compliant facilities because there just isn't much signal in their history. This means the model's main weakness is predicting first-time or sporadic violators, which is inherently hard when the approach relies on historical patterns.

\section{Discussion and Conclusion}
%% ============================================================

\subsection{Key Findings}

Our results show that compliance violations at small manufacturing facilities can be predicted with strong discrimination (AUC-ROC at or above 0.957 across all models) using historical compliance patterns and facility characteristics. Random Forest got the highest test AUC-ROC of 0.974 [0.972, 0.977], with XGBoost performing essentially the same at 0.974 [0.971, 0.977]. Both did noticeably better than Logistic Regression (0.960) and SVM (0.957), which is consistent with what the literature says about ensemble methods on tabular data \cite{chen2016}.

The SHAP analysis shows that the most important predictors are inspection count, distance since the last non-compliance event, informal enforcement action count, CWA program participation, and the count of non-compliant quarters in the feature window. The directions make intuitive sense: more inspections and more recent violations push the predicted violation probability up. The number of active regulatory programs also has a clear monotonic relationship with violation rates, going from about 4\% for facilities in just 1 program up to 43\% for those in 5 programs.

For the class imbalance experiments, all three strategies (no weighting, class weighting, SMOTE) gave similar AUC-ROC around 0.974. This suggests the models handle the 8\% imbalance fine on their own. No weighting actually came out slightly ahead on AUC-PR (0.833 vs 0.827 and 0.814).

\subsection{Limitations}

There are some limitations worth noting:

\begin{enumerate}
    \item \textbf{Cross-sectional snapshot}: Our pseudo-temporal split operates within a single data export. A proper temporal validation would use multiple quarterly snapshots, but those weren't readily available for this project.
    \item \textbf{Cumulative count features}: The lifetime inspection and penalty counts might include activity from the target period. The sensitivity analysis shows the effect is there but not dominant.
    \item \textbf{SVM scalability}: We had to train the RBF kernel SVM on just 12,000 rows, which might understate how well it could do with more data.
    \item \textbf{Small facility proxy}: ECHO doesn't have employee counts, so we used non-major regulatory status as a proxy for facility size. This is imperfect but it's what the data gives us.
\end{enumerate}

\subsection{Future Work}

There are a few directions we think this could go: (1) downloading multiple quarterly snapshots from ECHO to do real temporal validation, (2) pulling in the facility-level detail files from ECHO for richer inspection and enforcement features, (3) bringing in external data like Census County Business Patterns for better size estimates, and (4) potentially deploying this as a risk-scoring tool for regulatory targeting.
